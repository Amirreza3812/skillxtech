بازگشت به داشبورد تمرین این درس

طراحی وب

چارچوب‌های تست

یاد می‌گیریم تست خودکار چیست، یک تابع را با Vitest آزمایش کنیم و نتیجه‌ی تست‌ها را از ترمینال بخوانیم.

در این درس

    چرا کد را تست می‌کنیم؟

    وقتی تابعی می‌نویسیم، می‌توانیم چند ورودی به آن بدهیم و نتیجه را دستی بررسی کنیم. اما با بزرگ‌ترشدن پروژه، این بررسی وقت‌گیر می‌شود و ممکن است بعضی حالت‌ها را فراموش کنیم. تست خودکار کمک می‌کند رفتار مورد انتظار را در کد ثبت کنیم تا ابزار تست آن را بررسی کند.

    در این درس از Vitest استفاده می‌کنیم. Vitest یک چارچوب تست جاوااسکریپت است؛ تست‌ها را در فایل‌هایی می‌نویسیم و با دستور ترمینال اجرا می‌کنیم.

    تست چه چیزی را بررسی می‌کند؟

    تست معمولاً یک ورودی مشخص را به کد می‌دهد و بررسی می‌کند خروجی با نتیجه‌ی مورد انتظار برابر باشد.

    اجزای یک تست

    یک تست ساده سه بخش اصلی دارد: تابعی که می‌خواهیم بررسی کنیم، مقدار مورد انتظار، و بررسی‌ای که نتیجه‌ی واقعی را با انتظارمان مقایسه می‌کند. 

    // sum.js
export function sum(a, b) {
  return a + b;
}

    در فایل تست، تابع را وارد می‌کنیم. سپس با test() یک مورد تست تعریف می‌کنیم و با expect() نتیجه را بررسی می‌کنیم: 

    // sum.test.js
import { expect, test } from "vitest";
import { sum } from "./sum.js";

test("جمع دو عدد را برمی‌گرداند", () => {
  expect(sum(1, 2)).toBe(3);
});

    نام تست توضیح می‌دهد چه رفتاری را بررسی می‌کنیم. در این مثال، toBe(3) انتظار دارد نتیجه دقیقاً برابر با عدد 3 باشد. Vitest هم از it() به‌عنوان نام دیگری برای تعریف تست پشتیبانی می‌کند.

    بنویس که چه چیزی را می‌سنجی

    نام‌هایی مثل «تست یک» اطلاعات کمی می‌دهند. نامی روشن، مانند «جمع دو عدد را برمی‌گرداند»، کمک می‌کند بفهمیم تست چه رفتاری را بررسی می‌کند.

    بررسی‌های expect

    متدهای زنجیره‌شده به expect() را matcher می‌نامند. برای مقایسه‌ی مقدار دقیق می‌توان از toBe() استفاده کرد: 

    expect(sum(2, 3)).toBe(5);
expect("سلام").toBe("سلام");

    اگر نتیجه با مقدار مورد انتظار یکی نباشد، تست شکست می‌خورد. ابزار تست گزارش می‌دهد کدام تست شکست خورده و چه مقداری را انتظار داشته‌ایم.

    راه‌اندازی Vitest

    برای اجرای نمونه‌های این درس به Node.js و npm نیاز داری. در پوشه‌ی پروژه، Vitest را به‌عنوان وابستگی توسعه نصب کن: 

    npm install -D vitest

    سپس در بخش scripts فایل package.json، دستور test را تعریف کن: 

    {
  "scripts": {
    "test": "vitest"
  }
}

    حالا با اجرای دستور زیر، Vitest فایل‌های تست پروژه را پیدا و اجرا می‌کند: 

    npm run test

    فایل‌های تست به‌طور پیش‌فرض باید در نامشان .test. یا .spec. داشته باشند؛ برای نمونه، sum.test.js.

    این دستور در کادر تمرین اجرا نمی‌شود

    Vitest یک ابزار پروژه‌ای است و باید از ترمینال، در پوشه‌ی پروژه‌ای که Node.js و Vitest در آن نصب شده‌اند اجرا شود. کادرهای تعاملی این درس برای اجرای JavaScript ساده در مرورگرند، نه اجرای Vitest.

    تست چند حالت

    یک تابع ممکن است برای ورودی‌های مختلف رفتار متفاوتی داشته باشد. بهتر است حالت‌های مهم را با تست‌های جداگانه بررسی کنیم: 

    import { expect, test } from "vitest";
import { sum } from "./sum.js";

test("دو عدد مثبت را جمع می‌کند", () => {
  expect(sum(2, 3)).toBe(5);
});

test("عدد صفر را هم درست جمع می‌کند", () => {
  expect(sum(0, 4)).toBe(4);
});

test("عدد منفی را هم درست جمع می‌کند", () => {
  expect(sum(-2, 5)).toBe(3);
});

    هر تست باید رفتار مشخصی را بررسی کند. وقتی تستی شکست می‌خورد، نام آن کمک می‌کند سریع‌تر بفهمیم کدام حالت درست کار نمی‌کند.

    گروه‌بندی با describe

    اگر چند تست مربوط به یک تابع یا بخش باشند، می‌توان آن‌ها را با describe() زیر یک عنوان گروه‌بندی کرد: 

    import { describe, expect, test } from "vitest";
import { sum } from "./sum.js";

describe("تابع sum", () => {
  test("دو عدد مثبت را جمع می‌کند", () => {
    expect(sum(2, 3)).toBe(5);
  });

  test("عدد منفی را هم جمع می‌کند", () => {
    expect(sum(-2, 5)).toBe(3);
  });
});

    describe() تست‌های مرتبط را منظم می‌کند؛ هر تست داخل آن همچنان با test() تعریف می‌شود.

    امتحان کن: ایده‌ی یک بررسی ساده

    مثال زیر Vitest نیست؛ فقط ایده‌ی اصلی تست را در مرورگر نشان می‌دهد: یک مقدار واقعی را با نتیجه‌ی مورد انتظار مقایسه می‌کنیم و پیام موفقیت یا شکست می‌دهیم.

    تفاوت مثال با چارچوب تست

    در پروژه‌ی واقعی، Vitest تست‌ها را اجرا و گزارش را در ترمینال نمایش می‌دهد. نمونه‌ی بالا فقط مقایسه‌ی مقدارها را در مرورگر نشان می‌دهد و جایگزین راه‌اندازی Vitest نیست.

    جمع‌بندی

    تست خودکار رفتار مورد انتظار برنامه را بررسی می‌کند. در Vitest، با test() تست تعریف می‌کنیم، با expect() نتیجه را می‌سنجیم و می‌توانیم تست‌های مرتبط را با describe() گروه‌بندی کنیم. Vitest را در پروژه نصب می‌کنیم، تست‌ها را در فایل‌هایی مانند sum.test.js می‌نویسیم و با npm run test اجرا می‌کنیم.

    آماده‌ای؟

    در تمرین‌ها یک تابع می‌سازیم و رفتارهایش را با تست بررسی می‌کنیم.
