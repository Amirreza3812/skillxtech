طراحی وب

async و await

در این درس یاد می‌گیریم Promiseها را با ساختاری خواناتر مدیریت کنیم، نتیجه‌ی عملیات ناهمگام را دریافت کنیم و خطاها را با try...catch کنترل کنیم.

در این درس

    چرا async و await؟

    در درس قبل دیدیم که Promise راهی برای مدیریت نتیجه‌ای است که ممکن است در آینده آماده شود. می‌توان Promiseها را با .then() و .catch() مدیریت کرد. کلیدواژه‌های async و await همان کار را با ظاهری شبیه کد معمولی و مرحله‌به‌مرحله انجام می‌دهند.

    این کد منتظر یک عملیات ناهمگام می‌ماند، اما مرورگر و صفحه را قفل نمی‌کند؛ بخش وابسته‌ی همان تابع پس از آماده‌شدن نتیجه ادامه پیدا می‌کند.

    پیش‌نیاز

    برای فهم این درس، باید با تابع، Promise و fetch() آشنا باشی. درس قبل با عنوان «Promises و fetch» این مفاهیم را معرفی می‌کند.

    تابع async

    برای تعریف تابع ناهمگام، کلمه‌ی async را پیش از تعریف تابع می‌نویسیم. اجرای هر تابع async همیشه یک Promise برمی‌گرداند؛ حتی اگر در بدنه‌ی آن یک مقدار ساده برگردانیم. 

    async function getMessage() {
  return "سلام!";
}

getMessage().then((message) => {
  console.log(message);
});

    مقدار "سلام!" به Promise برگردانده‌شده تبدیل می‌شود. بنابراین می‌توان نتیجه را با .then() دریافت کرد.

    نکته

    تابع async الزاماً نباید درون خودش await داشته باشد؛ اما معمولاً این دو را با هم به‌کار می‌بریم تا با Promiseها خواناتر کار کنیم.

    منتظر ماندن با await

    عملگر await را داخل تابع async می‌نویسیم. اگر عبارت کنارش یک Promise باشد، اجرای ادامه‌ی همان تابع تا آماده‌شدن نتیجه مکث می‌کند و سپس مقدار موفقیت‌آمیز Promise در متغیر قرار می‌گیرد. 

    function waitForMessage() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve("پیام آماده شد");
    }, 1000);
  });
}

async function showMessage() {
  const message = await waitForMessage();
  console.log(message);
}

showMessage();

    در این مثال، waitForMessage() یک Promise برمی‌گرداند. await نتیجه‌ی آن را می‌گیرد و در message قرار می‌دهد. بدون await، متغیر به‌جای متن، خود Promise را دریافت می‌کرد.

    محدودیت استفاده

    در جاوااسکریپت معمولی، await را داخل تابع async بنویس. در فایل‌های ماژول، امکان استفاده از await در سطح بالای فایل هم وجود دارد.

    مدیریت خطا با try...catch

    اگر Promiseای که با await منتظرش هستیم رد شود (rejected)، مقدار خطا مانند یک استثنا پرتاب می‌شود. می‌توانیم await را درون بلوک try قرار دهیم و خطا را در بلوک catch مدیریت کنیم. 

    async function loadData() {
  try {
    const response = await fetch("https://example.com/data.json");
    const data = await response.json();

    console.log(data);
  } catch (error) {
    console.error("دریافت داده ناموفق بود:", error);
  }
}

loadData();

    در هر دو خط await ممکن است خطا رخ دهد: درخواست fetch() ممکن است شکست بخورد یا خواندن بدنه‌ی پاسخ با response.json() ممکن است موفق نشود. به همین دلیل هر دو خط درون try هستند.

    یادت باشد response.ok را بررسی کنی

    پاسخ‌هایی مانند خطای HTTP با کد 404 معمولاً باعث ردشدن Promise مربوط به fetch() نمی‌شوند. برای بررسی موفق‌بودن پاسخ HTTP، مقدار response.ok را کنترل کن و در صورت نیاز خودت خطا بساز. 

    async function loadData() {
  try {
    const response = await fetch("https://example.com/data.json");

    if (!response.ok) {
      throw new Error(`خطای HTTP: ${response.status}`);
    }

    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.error("بارگذاری داده ناموفق بود:", error);
  }
}

    نمونه‌ی کامل با fetch

    برای دریافت اطلاعات از یک API، معمولاً ابتدا پاسخ fetch() را با await می‌گیریم، سپس response.ok را بررسی می‌کنیم و در آخر بدنه‌ی پاسخ را با response.json() می‌خوانیم. 

    async function getPost() {
  try {
    const response = await fetch(
      "https://jsonplaceholder.typicode.com/posts/1"
    );

    if (!response.ok) {
      throw new Error(`خطای HTTP: ${response.status}`);
    }

    const post = await response.json();
    console.log(post.title);
  } catch (error) {
    console.error("خطا در دریافت نوشته:", error);
  }
}

getPost();

    فراخوانی fetch() و تبدیل پاسخ به JSON دو عملیات ناهمگام جداگانه‌اند؛ برای همین هرکدام را با await دریافت می‌کنیم.

    ترتیب اجرای چند عملیات

    وقتی چند عملیات به نتیجه‌ی قبلی وابسته‌اند، می‌توانیم آن‌ها را به‌ترتیب با await اجرا کنیم. هر خط پس از آماده‌شدن نتیجه‌ی خط قبلی ادامه پیدا می‌کند. 

    async function loadUserAndPosts() {
  const userResponse = await fetch("/api/user");
  const user = await userResponse.json();

  const postsResponse = await fetch(`/api/users/${user.id}/posts`);
  const posts = await postsResponse.json();

  return posts;
}

    اگر چند کار مستقل از یکدیگرند و می‌خواهیم هم‌زمان شروع شوند، نباید بی‌دلیل منتظر پایان هرکدام بمانیم. می‌توانیم Promiseهایشان را شروع کنیم و با Promise.all() منتظر همه‌ی نتیجه‌ها بمانیم. 

    async function loadPageData() {
  const usersPromise = fetch("/api/users");
  const productsPromise = fetch("/api/products");

  const [usersResponse, productsResponse] = await Promise.all([
    usersPromise,
    productsPromise
  ]);

  const users = await usersResponse.json();
  const products = await productsResponse.json();

  return { users, products };
}

    یک قاعده‌ی کاربردی

    اگر نتیجه‌ی عملیات دوم به نتیجه‌ی اول وابسته است، آن‌ها را با await به‌ترتیب اجرا کن. اگر مستقل‌اند، می‌توانی هر دو را شروع کنی و از Promise.all() کمک بگیری.

    خلاصه

    • async تابعی می‌سازد که همیشه Promise برمی‌گرداند.
    • await نتیجه‌ی Promise را می‌گیرد و ادامه‌ی همان تابع را تا آماده‌شدن نتیجه متوقف می‌کند.
    • برای مدیریت خطاهای عملیات ناهمگام از try...catch استفاده کن.
    • در درخواست‌های fetch()، response.ok را برای بررسی وضعیت HTTP کنترل کن.
    • برای عملیات مستقل می‌توان از Promise.all() استفاده کرد.

    آماده‌ای؟

    با چند تمرین، async و await را در کد خودت به‌کار ببر.
