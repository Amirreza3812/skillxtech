بازگشت به داشبورد تمرین این درس

طراحی وب

آشنایی با بک‌اند

با تفاوت فرانت‌اند و بک‌اند، نقش سرور و پایگاه داده و مسیر رفت‌وبرگشت یک درخواست آشنا می‌شوی.

در این درس

    ۱. فرانت‌اند و بک‌اند

    فرانت‌اند بخشی از وب‌سایت است که در مرورگر اجرا می‌شود و کاربر آن را می‌بیند یا با آن تعامل می‌کند؛ مثل دکمه‌ها، فرم‌ها، متن‌ها و چیدمان صفحه. HTML، CSS و JavaScript ابزارهای اصلی فرانت‌اند هستند.

    بک‌اند بخش برنامه است که معمولاً روی سرور اجرا می‌شود. بک‌اند می‌تواند درخواست‌های فرانت‌اند را بررسی کند، داده‌ها را پردازش کند، با پایگاه داده ارتباط بگیرد و پاسخی برگرداند.

    یک تصویر ساده

    فرانت‌اند را می‌توان بخش قابل‌مشاهده‌ی رستوران دانست؛ بک‌اند کارهایی را انجام می‌دهد که برای آماده‌سازی سفارش در پشت صحنه لازم‌اند. این تشبیه برای درک نقش‌هاست، نه این‌که وب‌سایت‌ها دقیقاً مثل رستوران کار کنند.

    ۲. سرور چیست؟

    سرور کامپیوتری یا محیطی است که برنامه‌ی بک‌اند را اجرا می‌کند و از طریق شبکه به درخواست‌ها پاسخ می‌دهد. وقتی مرورگر به یک وب‌سایت درخواست می‌فرستد، ممکن است سرور صفحه، داده یا پیامی را برگرداند.

    «سرور» گاهی به خودِ کامپیوتری گفته می‌شود که برنامه روی آن اجراست و گاهی به برنامه‌ای که درخواست‌ها را دریافت و مدیریت می‌کند. معنی دقیق آن به متن بستگی دارد.

    ۳. درخواست و پاسخ

    مرورگر و سرور معمولاً با الگوی درخواست و پاسخ با هم ارتباط برقرار می‌کنند:

    1. کاربر در صفحه کاری انجام می‌دهد؛ مثلاً دکمه‌ای را فشار می‌دهد.
    2. فرانت‌اند در صورت نیاز، درخواستی برای سرور می‌فرستد.
    3. سرور درخواست را بررسی می‌کند و ممکن است داده‌ای را پردازش کند.
    4. سرور پاسخی می‌فرستد و فرانت‌اند نتیجه را به کاربر نشان می‌دهد.

    نکته

    هر تعاملی در صفحه نیازمند بک‌اند نیست. مثلاً باز و بسته‌کردن یک منو می‌تواند فقط با JavaScript داخل مرورگر انجام شود. ذخیره‌کردن حساب کاربری یا دریافت اطلاعات مشترک میان کاربران معمولاً به بک‌اند نیاز دارد.

    ۴. بک‌اند و پایگاه داده

    پایگاه داده جایی برای سازمان‌دهی و نگهداری داده‌هاست؛ مانند حساب‌های کاربری، محصولات یا سفارش‌ها. برنامه‌ی بک‌اند می‌تواند براساس درخواست داده‌ای را از پایگاه داده بخواند یا آن را تغییر دهد.

    معمولاً مرورگر مستقیماً به پایگاه داده‌ی خصوصی برنامه وصل نمی‌شود. بک‌اند می‌تواند درخواست‌ها را بررسی کند و تنها داده‌های لازم را از طریق پاسخ به فرانت‌اند بفرستد.

    اطلاعات محرمانه را در فرانت‌اند نگذار

    کدی که به مرورگر ارسال می‌شود می‌تواند توسط کاربران بررسی شود. پس رمزها، کلیدهای خصوصی و اطلاعات حساس سرور را در فایل‌های JavaScript فرانت‌اند قرار نده. این اطلاعات باید در محیط امن بک‌اند مدیریت شوند.

    ۵. API چه نقشی دارد؟

    API مجموعه‌ای از راه‌های تعریف‌شده برای درخواست‌دادن به یک برنامه و دریافت پاسخ از آن است. فرانت‌اند می‌تواند از API بک‌اند بخواهد کاری انجام دهد یا داده‌ای دریافت کند.

    برای نمونه، یک برنامه‌ی فروشگاهی ممکن است راهی برای دریافت فهرست محصولات داشته باشد. فرانت‌اند درخواست می‌فرستد و پس از دریافت پاسخ، محصولات را در صفحه نمایش می‌دهد. جزئیات طراحی و پیاده‌سازی API در درس بعدی درباره‌ی fetch بررسی خواهد شد.

    ۶. بک‌اند با چه ابزارهایی ساخته می‌شود؟

    زبان‌ها و ابزارهای گوناگونی برای ساخت بک‌اند وجود دارند. در ادامه‌ی این دوره با Node.js آشنا می‌شویم که امکان اجرای JavaScript بیرون از مرورگر را فراهم می‌کند. Node.js به‌تنهایی تمام یک برنامه‌ی بک‌اند نیست؛ برای ساخت برنامه‌های وب می‌توان از چارچوب‌ها و ابزارهای دیگری هم در کنار آن استفاده کرد.

    ۷. امتحان کن: شبیه‌سازی یک پاسخ

    این مثال فقط در مرورگر یک پاسخ آزمایشی می‌سازد؛ به سرور یا پایگاه داده وصل نمی‌شود. پیام را تغییر بده و دکمه را بزن تا ببینی فرانت‌اند چگونه می‌تواند پاسخی را در صفحه نمایش دهد.

    ۸. جمع‌بندی

    فرانت‌اند در مرورگر اجرا می‌شود و رابطی را که کاربر با آن کار می‌کند می‌سازد. بک‌اند روی سرور درخواست‌ها را پردازش می‌کند و می‌تواند با پایگاه داده ارتباط بگیرد. فرانت‌اند و بک‌اند معمولاً از طریق API و الگوی درخواست و پاسخ با هم ارتباط دارند. کدهای قابل‌مشاهده‌ی فرانت‌اند جای مناسبی برای نگهداری اطلاعات محرمانه نیستند.

    آماده‌ای؟

    در تمرین‌ها نقش فرانت‌اند، بک‌اند و پایگاه داده را بررسی کن.
