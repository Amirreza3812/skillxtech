ارث‌بری در جاوااسکریپت

با ارث‌بری، کلاس‌های جدیدی می‌سازیم که ویژگی‌ها و رفتارهای کلاس دیگری را به ارث می‌برند و در صورت نیاز آن‌ها را گسترش می‌دهند.

در این درس

    ۱. ارث‌بری چه مشکلی را حل می‌کند؟

    گاهی چند کلاس ویژگی‌ها یا رفتارهای مشترکی دارند. برای مثال، Dog و Cat هر دو نام دارند و می‌توانند صدا تولید کنند. اگر این ویژگی‌ها را جداگانه در هر کلاس بنویسیم، بخشی از کد تکرار می‌شود.

    با ارث‌بری، ویژگی‌ها و متدهای مشترک را در یک کلاس پایه قرار می‌دهیم و کلاس‌های تخصصی‌تر را از آن می‌سازیم. در جاوااسکریپت، کلاس پایه را معمولاً «والد» و کلاسی را که از آن ارث می‌برد «فرزند» می‌نامیم.

    نکته

    ارث‌بری را زمانی به کار ببر که بین کلاس‌ها رابطه‌ی «نوعی از» وجود دارد؛ مثلاً سگ نوعی حیوان است. برای هر اشتراک ساده‌ای لازم نیست کلاس‌ها را به هم مرتبط کنیم.

    ۲. ساخت کلاس فرزند با extends

    برای ارث‌بری، نام کلاس فرزند را پس از class می‌نویسیم و با کلمه‌ی کلیدی extends کلاس والد را مشخص می‌کنیم. نمونه‌های کلاس فرزند می‌توانند از متدهای عمومی کلاس والد استفاده کنند. 

    class Animal {
  speak() {
    return "صدایی تولید می‌کند.";
  }
}

class Dog extends Animal {
}

const dog = new Dog();
console.log(dog.speak());

    در این مثال، کلاس Dog متد speak() را خودش تعریف نکرده است؛ اما چون از Animal ارث می‌برد، نمونه‌ی سگ می‌تواند آن متد را اجرا کند.

    ۳. سازنده‌ی والد و super

    اگر کلاس فرزند سازنده‌ی خودش را تعریف کند و بخواهد سازنده‌ی کلاس والد را هم اجرا کند، باید super() را در سازنده‌ی فرزند فراخوانی کند. مقدارهایی که به super() می‌دهیم به سازنده‌ی والد فرستاده می‌شوند.

    در سازنده‌ی یک کلاس فرزند، پیش از استفاده از this باید super() اجرا شود. این کار بخش مشترک نمونه را در کلاس والد مقداردهی می‌کند؛ سپس می‌توانیم ویژگی‌های مخصوص کلاس فرزند را اضافه کنیم. 

    class Animal {
  constructor(name) {
    this.name = name;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);
    this.breed = breed;
  }
}

const dog = new Dog("برفی", "هاسکی");
console.log(dog.name);
console.log(dog.breed);

    هشدار

    اگر در کلاس فرزند سازنده تعریف کرده‌ای، قبل از استفاده از this حتماً super() را فراخوانی کن؛ وگرنه خطا دریافت می‌کنی.

    ۴. بازنویسی متد والد

    کلاس فرزند می‌تواند متدی با همان نام متد والد تعریف کند. در این حالت، هنگام فراخوانی آن متد روی نمونه‌ی فرزند، نسخه‌ی تعریف‌شده در کلاس فرزند اجرا می‌شود. به این کار «بازنویسی» یا override می‌گویند. 

    class Animal {
  speak() {
    return "صدایی تولید می‌کند.";
  }
}

class Cat extends Animal {
  speak() {
    return "میو!";
  }
}

const cat = new Cat();
console.log(cat.speak());

    اگر بخواهیم متد بازنویسی‌شده‌ی فرزند، نسخه‌ی والد را هم اجرا کند، می‌توانیم از super درون متد استفاده کنیم؛ برای مثال: super.speak().

    ۵. استفاده از متد والد با super

    super فقط برای سازنده نیست. در متدهای کلاس فرزند نیز می‌توانیم با نوشتن super.methodName() متد متناظر کلاس والد را فراخوانی کنیم. 

    class Animal {
  constructor(name) {
    this.name = name;
  }

  describe() {
    return `${this.name} یک حیوان است.`;
  }
}

class Dog extends Animal {
  describe() {
    return `${super.describe()} این حیوان سگ است.`;
  }
}

const dog = new Dog("برفی");
console.log(dog.describe());

    ۶. امتحان کن

    کلاس Vehicle را به‌عنوان کلاس والد کامل کن و از آن کلاس Car را بساز. کلاس فرزند باید ویژگی doors داشته باشد و متد توضیح را بازنویسی کند.

    ۷. اشتباه‌های رایج

    • برای ارث‌بری، کلاس والد را بعد از extends بنویس.
    • اگر کلاس فرزند سازنده‌ی خودش را دارد، پیش از استفاده از this، سازنده‌ی والد را با super() فراخوانی کن.
    • super() سازنده‌ی والد را اجرا می‌کند؛ اما super.methodName() یک متد والد را فراخوانی می‌کند.
    • اگر کلاس فرزند متدی همنام با متد والد داشته باشد، نسخه‌ی فرزند هنگام فراخوانی روی نمونه‌ی فرزند اجرا می‌شود.

    ۸. جمع‌بندی

    با extends یک کلاس را از کلاس دیگری مشتق می‌کنیم. کلاس فرزند می‌تواند متدهای والد را به ارث ببرد، متدهای خودش را اضافه کند یا متدهای والد را بازنویسی کند. در سازنده‌ی فرزند، برای اجرای سازنده‌ی والد از super() استفاده می‌کنیم و برای فراخوانی متد والد می‌نویسیم super.methodName().

    آماده‌ای؟

    با ساخت کلاس‌های والد و فرزند، ارث‌بری را تمرین کن.
