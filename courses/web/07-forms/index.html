طراحی وب

فرم‌ها

یاد بگیر فرم برای چیست، کادرها را داخل آن بگذار و اطلاعات را آماده‌ی ارسال کن.

در این درس

    فرم چیست و برای چه کاری است؟

    در درس قبل کادرهای متنی ساختیم، ولی آن کادرها فقط روی صفحه بودند و اطلاعاتشان جایی نمی‌رفت. فرم کادرها را کنار هم می‌گذارد و اطلاعات داخلشان را برای ارسال آماده می‌کند، مثل یک برگه‌ی ثبت‌نام کاغذی که پر می‌کنی و تحویل می‌دهی.

    تقریباً هر جا که از کاربر چیزی می‌گیری، فرم داری:

    • ثبت‌نام و ورود به حساب
    • کادر جستجو (حتی کادر جستجوی گوگل یک فرم است)
    • نظر دادن و تماس با ما
    • سفارش دادن و پرداخت

    وقتی فرم ارسال می‌شود چه اتفاقی می‌افتد؟

    1. کاربر کادرها را پر می‌کند.
    2. روی دکمه‌ی ارسال کلیک می‌کند.
    3. مرورگر اطلاعات همه‌ی کادرها را جمع می‌کند و به یک آدرس (که ما مشخص کرده‌ایم) می‌فرستد.
    4. یک برنامه در سرور آن اطلاعات را می‌گیرد و کاری با آن می‌کند، مثلاً حساب می‌سازد یا پیام را ذخیره می‌کند.
    5. سرور یک صفحه‌ی جواب برمی‌گرداند، مثلاً «ثبت‌نام شد».

    در این درس روی قسمت‌های ۱ تا ۳ کار می‌کنیم، یعنی ساختن فرم و آماده کردن اطلاعات. قسمت ۴ (برنامه‌ی سرور) بعداً در درس‌های برنامه‌نویسی می‌آید.

    GitHub Pages سرور ندارد

    GitHub Pages فقط فایل‌های آماده را نمایش می‌دهد و هیچ برنامه‌ای برای دریافت اطلاعات فرم ندارد. اگر فرم را آنجا بگذاری، ارسالش اطلاعاتی را ذخیره نمی‌کند. برای دریافت واقعی اطلاعات باید فرم را به یک سرویس آماده بفرستی (مثل Google Forms یا سرویس‌های فرم‌ساز که قیمت و محدودیت‌هایشان را باید جدا چک کنی)، یا بعداً سرور خودت را بنویسی. تا آن موقع، هدف ما ساختن فرم درست و خوشگل است.

    یک فرم از تگ form ساخته می‌شود که کادرها و یک دکمه‌ی ارسال داخل آن هستند. مهم‌ترین نکته‌اش ویژگی name است. بیا یکی بسازیم:

    چیزی را بنویس و دکمه‌ی «ارسال» را بزن. کادر پایین نشان می‌دهد اگر سرور وجود داشت چه اطلاعاتی برایش می‌رفت. بخش <script> فقط برای نمایش همین کادر است و به JavaScript مربوط است که بعداً یاد می‌گیریم. فعلاً لازم نیست آن را بفهمی.

    بخشکاربرد
    <form>همه‌ی کادرها و دکمه‌ی ارسال داخل آن قرار می‌گیرند
    name روی هر کادراسمی که اطلاعات آن کادر با آن ارسال می‌شود
    id روی هر کادربرای وصل کردن label و برای CSS و JavaScript
    button type="submit"دکمه‌ای که فرم را ارسال می‌کند

    بدون name چیزی ارسال نمی‌شود

    اگر کادری name نداشته باشد، مقدارش ارسال نمی‌شود، هرچند کاربر داخلش چیزی نوشته باشد. در کد بالا name="email" را پاک کن و دوباره ارسال را بزن تا ببینی ایمیل از خروجی می‌افتد.

    id یا name؟

    id برای متصل کردن label و CSS است و name برای ارسال اطلاعات. معمولاً هر دو را می‌نویسیم و می‌توانند یکی باشند. مقدار id باید در صفحه یکتا باشد، ولی چند کادر می‌توانند name یکسان داشته باشند (مثل گزینه‌های یک رادیو).

    اطلاعات چطور ارسال می‌شود؟

    اطلاعات فرم به شکل جفت‌های name = value ارسال می‌شود. برای کادرهای متنی، value همان چیزی است که کاربر نوشته. برای گزینه‌ها، مقدار را خودمان با ویژگی value مشخص می‌کنیم:

    با گزینه‌های مختلف چند بار امتحان کن و این‌ها را ببین:

    • رادیو: گزینه‌های یک گروه باید name یکسان داشته باشند تا فقط یکی انتخاب شود. مقدار گزینه‌ی انتخاب‌شده ارسال می‌شود.
    • چک‌باکس: فقط تیک‌خورده‌ها ارسال می‌شوند. اگر چند تا تیک بخورد، چند خط با name یکسان ارسال می‌شود. اگر هیچ‌کدام تیک نخورد، اصلاً چیزی نمی‌رود.
    • لیست کشویی: value گزینه‌ی انتخاب‌شده ارسال می‌شود، نه متن نمایش‌داده‌شده.

    action و method

    دو ویژگی روی تگ form مشخص می‌کنند اطلاعات کجا و چطور برود:

    <form action="/signup" method="post">
  ...
</form>
    ویژگیمعنی
    actionآدرسی که اطلاعات به آن فرستاده می‌شود. اگر ننویسی، به همان صفحه‌ی فعلی می‌رود.
    methodروش ارسال: get (پیش‌فرض) یا post

    get یا post؟

    • get: اطلاعات به انتهای آدرس اضافه می‌شود. اگر کاربر در فرم بالا نام Ali و ایمیل ali@example.com را بنویسد، آدرس می‌شود: 
      result.html?username=Ali&email=ali%40example.com
      مناسب جستجو و فیلتر است، چون می‌شود آدرس را ذخیره یا برای کسی ارسال کرد.
    • post: اطلاعات داخل بدنه‌ی درخواست می‌رود و در آدرس دیده نمی‌شود. برای اطلاعات خصوصی، طولانی یا کارهایی که چیزی را تغییر می‌دهند مثل ثبت‌نام و رمز عبور از آن استفاده می‌کنیم.

    چرا در کادرهای این درس ارسال واقعی نمی‌شود؟

    سرور واقعی وجود ندارد، پس در کادرهای «امتحان کن» با یک کد کوچک ارسال را متوقف می‌کنیم و فقط اطلاعاتی را که فرستاده می‌شد نشان می‌دهیم. برای دیدن ارسال واقعی، کد فرم را در یک فایل .html روی کامپیوترت ذخیره کن. در تمرین این درس همین کار را می‌کنی.

    رمز عبور را با get نفرست

    اطلاعات get در آدرس می‌ماند و در تاریخچه‌ی مرورگر ذخیره می‌شود. برای رمز عبور و اطلاعات خصوصی همیشه از post و آدرس امن (https) استفاده می‌شود.

    دکمه‌ها

    دکمه‌های فرم سه نوع دارند:

    نوعکاری که می‌کند
    type="submit"فرم را ارسال می‌کند
    type="reset"همه‌ی کادرها را به حالت اول برمی‌گرداند
    type="button"هیچ کاری نمی‌کند (برای JavaScript بعدی)

    نوع پیش‌فرض دکمه، submit است

    اگر داخل فرم یک <button> بدون type بنویسی، آن هم مثل submit فرم را ارسال می‌کند. برای دکمه‌ای که نباید ارسال کند حتماً type="button" بنویس. دکمه باید داخل تگ form باشد تا فرم را ارسال کند.

    اعتبارسنجی ساده با HTML

    مرورگر می‌تواند قبل از ارسال فرم، بعضی چیزها را خودش چک کند. اگر مقداری درست نباشد، پیام خطا نشان می‌دهد و فرم را ارسال نمی‌کند. فقط کافی است ویژگی‌های مناسب را بنویسی:

    ویژگیکاربرد
    requiredپر کردن کادر اجباری است
    minlength و maxlengthکمترین و بیشترین تعداد حرف
    min و maxکمترین و بیشترین مقدار برای عدد و تاریخ
    type="email" و type="url"مرورگر قالب ایمیل و آدرس سایت را چک می‌کند
    patternمقدار باید با یک الگو بخواند (الگوها را «عبارت منظم» می‌نامند)

    اول فرم را خالی ارسال کن و پیام مرورگر را ببین. بعد با مقدارهای نامعتبر (ایمیل بدون @، سن ۵) امتحان کن. فقط وقتی همه‌چیز درست باشد، کادر خروجی چیزی نشان می‌دهد. شماره‌ی موبایل اجباری نیست، ولی اگر نوشته شود باید با الگو بخواند. بخش 09[0-9]{9} یعنی «۰۹ و بعد دقیقاً ۹ رقم».

    اعتبارسنجی HTML امنیت نیست

    کاربر می‌تواند با DevTools این ویژگی‌ها را پاک کند و مقدار نامعتبر بفرستد. اعتبارسنجی HTML فقط برای راحتی کاربر است. هر برنامه‌ی سروری که اطلاعات را می‌گیرد باید دوباره همه‌چیز را چک کند.

    برچسب و گروه‌بندی

    یک فرم خوب برای همه قابل استفاده است. دو کار ساده کمک می‌کند:

    • همیشه label بگذار: یا با for و id، یا با گذاشتن کادر داخل label. کلیک روی برچسب، کادر را انتخاب می‌کند و برای گزینه‌های رادیو و چک‌باکس باعث می‌شود سطح کلیک بزرگ‌تر شود.
    • گزینه‌های مرتبط را با fieldset و legend گروه کن: fieldset یک قاب دور گروه می‌کشد و legend عنوان آن است. نرم‌افزارهای کمکی از آن می‌فهمند این گزینه‌ها یک سؤال‌اند.

    یک فرم کامل و زیبا

    حالا هر چیزی که یاد گرفتی را کنار هم می‌گذاریم: ساختار فرم، label، کادرهای استایل‌داده با :focus، و یک دکمه با hover و transition:

    box-sizing: border-box

    در این کد box-sizing: border-box را روی کادرها نوشتیم. معمولاً width فقط عرض محتواست و padding و border به آن اضافه می‌شوند. با border-box عرضی که می‌نویسی شامل padding و border هم می‌شود. بدون آن، کادر با عرض 100% از فرم بیرون می‌زند.

    اشتباه‌های رایج

    • یادت رفته name بدهی. مقدار آن کادر ارسال نمی‌شود.
    • رادیوهای یک گروه با name متفاوت. کاربر می‌تواند چند تا را با هم انتخاب کند و هیچ‌کدام از هم‌گروه بودن خبر ندارند.
    • for و id که یکی نیستند. کلیک روی label کادر را انتخاب نمی‌کند.
    • دکمه‌ی بیرون از form. دکمه کار نمی‌کند، چون به هیچ فرمی وصل نیست.
    • دکمه‌ی بدون type داخل فرم. فرم را ارسال می‌کند، حتی اگر نمی‌خواستی.
    • گذاشتن placeholder به‌جای label. با شروع تایپ ناپدید می‌شود و کاربر یادش می‌رود کادر چه بود.
    • فرستادن اطلاعات خصوصی با get. در آدرس دیده می‌شود.
    • تکیه‌ی کامل به اعتبارسنجی HTML. فقط راحتی کاربر است و امنیت نیست.
    • انتظار ذخیره‌شدن اطلاعات روی GitHub Pages. آنجا سروری برای دریافت اطلاعات نیست.
